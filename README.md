# ir-analyzer

企業が開示しているIR資料だけを根拠に、業績を分析・壁打ちするツール。

公開URL: https://ir-analyzer-beta.vercel.app/

## 目的

決算短信・決算説明資料などのPDFを取り込み、その範囲内だけで質問に答えさせる。
最優先事項はハルシネーション防止。資料に書かれていないことは答えさせない。

## 使い方

1. IR資料の一覧ページのURLを最大3つ入力して「取り込む」
2. 資料棚に取り込まれたPDFから、不要なもののチェックを外す
3. 選択中の資料だけを根拠に質問する

## 構成

- Next.js (App Router / JavaScript)
- TypeScript・Tailwindは不使用（意図的にシンプル構成）
- GitHubにコミット → Vercelが自動デプロイ
- 環境変数 `ANTHROPIC_API_KEY` はVercel側に設定（リポジトリには含めない）

### ファイル

    app/
      layout.js              全ページ共通の枠
      page.js                画面本体（取り込み・資料棚・質問）
      globals.css            スタイル
      api/
        collect/route.js     PDFリンク収集 → テキスト抽出
        chat/route.js        資料をもとに回答生成

### 処理の流れ

1. cheerio でページ内のPDFリンクを収集
2. pdf-parse でPDFからテキスト抽出（PDFファイル自体は保存しない）
3. 抽出テキストをブラウザのlocalStorageに保存
4. 質問時、選択中の資料テキストをsystemに載せてClaude APIへ

## ハルシネーション対策

- temperature 0
- 出典の明記を義務化（どの資料由来か追跡できるように）
- 原文引用を義務化（数値を述べるとき、資料の該当箇所をそのまま抜き出させる）
- 記載がない場合は推測せず「記載がありません」と明記させる
- 検索機能は持たせない（資料棚以外に情報源を存在させない）
- 計算値には「（資料の数値から算出）」を明記させる

原文引用は「AIが正しい証明」ではなく、人間が数秒で裏取りできるようにするための仕組み。
投資判断に直結する数値は必ずPDF原本で確認する前提。

## 既知の課題

### 表組みの抽出崩れ

pdf-parse は文字を順番に吐き出すだけなので、決算短信のような表の多いPDFでは
行と列の対応が崩れることがある。AIは受け取ったテキストに忠実なため、
この段階のズレは検出できない（原文引用も崩れたまま出る）。

対策候補:
- A: PDFをClaude APIに直接渡す（精度↑ / コスト3〜5倍・低速・ページ数上限あり）
- B: PDF構造解析の外部サービスを挟んでMarkdown化してから渡す
- C: テキスト直接貼り付け欄を用意し、読めない資料だけ手動で入れる

未決定。まず実データで抽出精度を確認してから判断する。

### JavaScriptで描画されるIRページに非対応

年度セレクタで選択して初めてPDFが表示されるタイプのページは、
HTML取得時点でリンクが存在しないため収集できない。
例: 守谷輸送機工業 https://moriya-elevator.co.jp/ir/library/results/

対策候補: ヘッドレスブラウザの導入、またはEDINET/TDnetからの直接取得。
後者なら企業ごとのサイト構造差から解放される。

### 目次ページを指定すると無関係なPDFが混ざる

IRトップページなどを指定すると、ヘッダーメニュー内の会社案内PDFを拾ってしまう。
資料棚のチェックボックスで手動除外する運用でカバーしている。

## 制限値

- 1URLあたり最大8件、合計15件までのPDFを取り込む
- 1PDFあたり30,000字まで
- 質問1回で送る資料は合計150,000字まで
- Vercelの実行時間上限は60秒

## コスト

Claude APIの従量課金。質問を実行したときのみ発生する。
資料棚に多くの資料を残したまま質問すると、毎回その全文を送るため割高になる。
不要な資料はチェックを外すか削除する。
